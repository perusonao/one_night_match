## 1. 目的

現行の `energy` モード（技カードと技エネルギーカードの2層構造、固有技1試合1回制限、
エンドゲームAI等 — Ver.0.9〜0.9.2で正式採用済み）は、システムレベルの安定化
（引き分け率0%、200ターン膠着解消、終盤停滞解消）を達成した。

Technique Deck Rules は、この安定した基盤の上に **「通常技・固有技・フィニッシャーを
すべてカードとして扱う」** という、より深いデッキ構築性とカードゲーム的な駆け引きを
導入するための次世代ルール案である。

本ルールの目的は以下の3点に整理される。

1. レスラーカードから技を直接無制限に使う現行方式を廃し、技カードの手札・デッキ・
   捨て札という資源循環を導入することで、デッキ構築の戦略性を高める。
2. 「対応カードなしのエネルギー防御」「連続攻撃」「フィニッシャー発動キャンセル」など、
   プロレスの攻防（返し合い、逆転劇）をより明示的にモデル化する。
3. 既存の `classic` / `energy` モードを一切破壊せず、独立した第3のモードとして
   共存させ、将来的な移行判断（採用・破棄・部分採用）の余地を残す。

## 2. 現行ルールとの違い

| 観点 | classic | energy（現行, Ver.0.9.2時点） | Technique Deck（本案） |
|---|---|---|---|
| 固有技・フィニッシャーの所在 | レベルカードに登録、セットカード消費で使用 | レベルカードに登録、技エネルギーで使用 | **手札のカードとして所持・使用** |
| 固有技の使用制限 | 無制限（再セットで反復可） | 1試合1回（Ver.0.9.1正式採用） | 未決定（デッキ内の同名枚数制限に置き換わる可能性、7章参照） |
| 通常技の扱い | 無料・コスト不要 | 技カード化、使用後は使い回し可（`BasicCardPolicy.unlimitedReuse`、Ver.0.9.2正式採用） | 通常技もデッキ内の1枚のカードとして消費・捨て札化（暫定、13章参照） |
| 防御の手段 | 速度クラッシュ（対応技カード） | 速度クラッシュ + 返し技（`isCounterMove`） | **対応カード不要のエネルギー防御**（7章）＋連続攻撃 |
| フィニッシャー無効化 | なし（自動フォールへ直行） | なし | **エスケープカード／リバーサルカードによる発動キャンセル**（8章） |
| フォール／ギブアップの回避 | キックアウトカード／HP消費 | 同左 | 同左の仕組みを技カードのパラメータ化で精緻化（9・10章） |
| ダウン・疲労 | 打撃KOでダウン付与のみ | 同左 + 山札切れ疲労 + HP0時TKO（`koStoppage`、Ver.0.9.1） | **スタンド／ダウン／疲労の3状態**を明示管理、疲労時は即敗北ではない（11章） |
| 試合時間切れ | 引き分け（任意設定） | 同左 | 引き分け（14章、HP/HEAT判定なし） |
| HP0の扱い | 即敗北ではない（`hpZeroReachedTurn`記録のみ） | 山札切れ＋HP0でTKO敗北 | **即敗北ではない。疲労→ダウン→試合継続**（14章、行動制限は未決定） |
| CPU AI | `_scoreMoveFor`ベース、`CpuDifficulty`（normal/strong/random, Ver.1.0） | 同左 | 新モード専用AI（Phase 8、8章のリソース温存判断が追加要件） |

**設計方針として明記する非対称点**: Technique Deck は `classic`/`energy` の代替では
なく、独立した並存モードである。既存2モードの数値・挙動（特に `energy` の
`signatureOncePerMatch` / `BasicCardPolicy` / `EnergySurplusPolicy` / `CpuDifficulty` /
`_isEndGameMode` などVer.0.9系・Ver.1.0系の到達点）は一切変更しない。

## 3. カード種別

最低限、以下の8種別を区別する。

```
WrestlerCard
TechniqueCard
TechniqueEnergyCard
EscapeCard
ReversalCard
KickOutCard
RopeBreakCard
ActionCard
```

`TechniqueCard` はさらに以下3区分を持つ。

```
normal      // 通常技
signature   // 固有技
finisher    // フィニッシャー
```

既存の `MoveCategory { normal, counter, finisher, basic }`（`lib/src/wrestler_editor/models.dart`）
との関係は **Phase 1で確定済み**。案B（新設案）を採用し、Technique Deck専用の
`TechniqueCardCategory { normal, signature, finisher }`（`lib/src/technique_deck/
technique_deck_models.dart`）を新設した。既存 `MoveCategory` には一切手を
入れていない。`classic`/`energy` への影響はゼロ。`MoveDefinition` との対応付けは
`TechniqueDeckTechniqueCard.sourceMoveId`（任意・Phase 1では保持のみ）で行う。

`KickOutCard`（後述4章・9章）についても、通常のフォールから脱出する
「通常キックアウト」と、フィニッシャー成立後の脱出専用である「特殊キックアウト」を
区別するため、Phase 2で `KickOutCardCategory { normal, finisherEscape }` を
`TechniqueDeckCardType.kickOut` のサブタイプとして追加した（`TechniqueDefenseCard.
kickOutCategory`、`kickOut` 以外の種別では未設定＝null）。

`WrestlerCard` は以下の情報を持つ（現行 `WrestlerDefinition` / `PlayerLevelMatchState`
から流用・拡張する想定）。

- 最大HP／現在HP
- 打・関・投などの攻撃補正
- 各属性への防御力（現行 `WrestlerLevelDefinition.resistances` 相当）
- 回復力（`recoveryPower` — 新規、11章参照）
- レベル／レベル解放条件（現行 `unlockCondition` 相当）
- 特殊能力（現行 `abilityId` — ただし現行エンジンでは能力はゲームプレイに
  未接続。Technique Deck で接続するかは未決定）
- 使用可能な固有技カード一覧
- 使用可能なフィニッシャーカード一覧

固有技・フィニッシャーはレスラーカードから直接使用しない。該当カードをデッキへ
入れ、手札から使用する。

## 4. デッキ構築

デッキ枚数は現時点で既存の30枚（`kDeckSize`、`lib/src/level_match/level_match_deck_builder.dart`）
を暫定維持する。**これは固定ルールではなく暫定値**であり、Phase 2の設計時に
再検討してよい。

構成例（参考値、固定ルールではない）:

| カード種別 | 参考枚数 |
|---|---|
| 技エネルギーカード（属性別合計） | 14〜18枚 |
| 通常技カード | 4〜6枚 |
| 固有技カード | 4〜6枚 |
| フィニッシャーカード | 1〜3枚 |
| 防御・特殊カード（キックアウト／ロープブレイク／エスケープ／リバーサル） | 2〜4枚 |

フィニッシャーについては以下を **確定仕様** とする。

- デッキに最大3枚まで投入可能
- 同名フィニッシャーは投入不可（3枚入れる場合はすべて異なる名称）
- レスラーが使用可能なフィニッシャーのみ投入可能
- 発動条件（8.1章）を満たした場合のみ使用可能

特殊キックアウトカードも最大3枚を **暫定仕様** とする（フィニッシャー同様の
「複数種の切り札を持てるが乱発できない」バランス意図。要検証）。

### 4.1 使用可能レスラーの指定（Phase 2で確定）

- 通常技・汎用防御カード（技エネルギー／エスケープ／リバーサル／通常キックアウト／
  ロープブレイク／アクション）: `allowedWrestlerIds` が空リスト＝全レスラー使用可能。
- 固有技・フィニッシャー: `allowedWrestlerIds` の指定が **必須**。空リストのまま
  デッキに投入するとデッキ検証エラー（`emptyAllowedWrestlerIds`）。

### 4.2 同名カード上限（Phase 2で確定、暫定値）

30枚デッキにおける同名カード（同一`name`）の上限を以下のとおり定める。
数値は暫定であり、実プレイテストの結果次第で調整しうる。

| カード種別 | 同名上限 |
|---|---|
| 通常技 | 3枚 |
| 固有技 | 1枚 |
| フィニッシャー | 1枚（かつデッキ全体で最大3枚、すべて別名） |
| 技エネルギーカード | 制限なし |
| エスケープカード | 2枚 |
| リバーサルカード | 2枚 |
| 通常キックアウトカード | 2枚 |
| 特殊キックアウトカード | 1枚（かつデッキ全体で最大3枚） |
| ロープブレイクカード | 2枚 |
| アクションカード | 3枚 |

固有技を1枚に制限することで、旧ルールの「固有技1試合1回」制限をデッキ構成として
自然に継承する意図がある。

以下は引き続き **未決定事項**（[open questions](../design/technique_deck_open_questions.md) 参照）として残す。

- エネルギーカードと技カードの推奨比率の正式な数値（Phase 2の検証では暫定の
  警告閾値のみを用いる）
- デッキポイント制（現行 `MoveDefinition.deckPoints`）を引き続き使用するか

## 5. ターン進行

新モードの暫定ターン構成:

1. ターン開始
2. 自分のレスラーをスタンド状態へ戻す（11.4章）
3. 使用済みエネルギーを回復（3.3章）
4. ドロー
5. エネルギーセット
6. レベル変更
7. メインアクション（技の使用、または休息の選択）
8. 技の連続使用・返技処理（7章）
9. 決着判定
10. ターン終了

HP0による疲労状態（11章）、または休息（12章）を選んだ場合には一部処理が変化する。
詳細な状態遷移図は実装計画 Phase 3 で作成する（本書では確定させない）。

## 6. 技の使用

自分のターンに、必要な技エネルギーを消費して、手札から通常技または固有技を
使用できる。

使用条件（すべて満たす必要がある）:

- 必要な技エネルギーを支払える（`attackEnergyCost`）
- レベル条件を満たす（`minimumLevel`）
- 使用レスラー条件を満たす（`allowedWrestlers`）
- 自分と相手の状態条件を満たす（`targetState`、11.3章）
- フィニッシャーの場合は発動条件を満たす（8.1章）

使用した技カードは、成立・防御の成否にかかわらず、原則として捨て札へ送る
（暫定仕様。フィニッシャーが発動キャンセルされた場合のみ例外的に山札へ戻す。
8.2章参照）。

## 7. 返技と連続攻撃

### 7.1 通常の防御（Phase 5で確定）

防御側は対応カードを出さなくても、技カードに設定された返技エネルギー
（`reversalEnergyCost`）を支払うことで技を防御（返技）できる。

確定仕様（Phase 5実装済み）:

- 対応カードは不要
- 返技エネルギーが足りていても、**返技するかどうかは防御側が任意に選べる**
  （読み合いの核。エネルギーを温存してあえて技を受ける選択も可能）
- 返技すると技は完全に無効（ダメージ0・HEAT加算なし・ダウン、フォール、
  ギブアップなどの付随効果もすべて無効）
- 返技しない場合は技が成立し、ダメージ・HEAT・ダウンが即時反映される
  （7.3章）
- 攻撃側の技カードは、宣言した時点で（成立・返技を問わず）手札から捨て札へ
  送る

これは現行 `energy` モードの「返し技（`isCounterMove`、`clashBetween`のcounter判定）」
とは設計思想が異なる。現行モードは「特定の返し技カードで、特定属性の攻撃を
クラッシュ判定で打ち消す」方式（Ver.1.1で `counter_brainbuster` の `counterTypes`
不足が主要バランス問題の原因と判明した機構）だが、本モードは「対応カード不要、
返技エネルギーさえあれば防げる（ただし防ぐかどうかは選択制）」というより
単純だが読み合いのある防御方式を採る。なお現行モードで判明した「唯一の返し技が
特定属性にしか対応していない」ような構造的な穴を、Technique Deck では属性ごとの
`reversalEnergyCost` を各技カードが個別に持つことで避けられる設計を意図している
（未検証）。

### 7.2 連続攻撃（Phase 5で確定）

**返技が成功すると、攻守が即座に入れ替わる。** 新しく攻撃側になったプレイヤー
（元の防御側）は、通常技・固有技のどちらでも次の技を宣言できる。これを
繰り返すことで「技→返技→攻守交代→技→返技→…」という応酬（ラリー）が
成立する。

> 草案時点（Phase 0）では「防御された場合、元の攻撃側が別の技を出す」という
> 設計も検討したが、Phase 5では不採用とした。返技＝反撃の起点という
> プロレスの実感（リバーサルで形勢が入れ替わる）に近く、応酬としての
> 読み合いがより明確になるため。

ラリーは以下のいずれかの条件を満たすまで繰り返す。

- 防御側が返技エネルギーを支払わない（選ばない）
- 防御側が返技エネルギーを支払えない（不足）
- 攻撃側が追加カードを出さない（ラリーを終了する）
- 攻撃側の手札に使用可能な技カードがない
- 最大反復回数（`TechniqueMatchEngine.maxRallyChain` = 20）に到達する

決着判定（フォール／ギブアップ／フィニッシャー）を持つ技が成立した場合の
ラリー終了は、決着処理自体がPhase 6・7で実装されるまでは対象外（Phase 5では
`hasPinEffect`等のフラグは保持されるのみで、決着処理へは接続しない）。

**実装上の安全弁**: ルール仕様上は使用上限なしだが、エンジン内部には
最大反復回数のハードキャップ（`maxRallyChain`）を実装済み。到達した場合は
ラリーを強制終了し、ログに記録する（Chain Limit）。

### 7.3 ダメージ

同一ターン中に成立した各技のダメージは加算する。

例:
```
技A 10ダメージ：成立
技B  8ダメージ：成立
技C 15ダメージ：防御
合計ダメージ：18
```

**Phase 4での判断**: 単発技のみを扱うPhase 4では即時適用と一括適用の結果に
差が出ないため、即時適用を「暫定ではなく現時点の有力候補」として実装した
（`TechniqueMatchEngine.useMove`）。技の成立ごとにHP・HEAT・ダウン状態を
即座に反映する。理由: 技Aの成立で相手がダウンし、直後にダウン限定技Bが
使用可能になる（`targetState`による判定）という連携を成立させるには
即時反映が必要なため。Phase 5（連続攻撃）でもこの方式を維持する方が自然と
考えているが、連続攻撃の実装時に問題が無いか改めて検証する
（open questions 1番、正式決定はPhase 5）。

- 即時適用案（採用）: 各技成立のたびにHPを減算する。途中でHPが閾値を割り込み、
  対象状態（`targetState`）や解放条件（レベル解放等）が変化しうる。演出上は
  「積み重なっていく」実感が出やすい。
  現行 `energy` モードのダメージ即時適用（`_land()`）と挙動的に近い。
- 一括適用案（不採用の候補として記録）: 連続攻撃の終了時点でまとめて減算する。
  連続攻撃中の状態変化が発生しないため実装は単純だが、「技Aで相手がダウンし、
  技Bがダウン限定技」のような連携を即時反映できない。

## 8. フィニッシャー

### 8.1 発動

フィニッシャーカードは、カードごとの発動条件（`finisherRequirements`）を
満たした場合のみ使用できる。条件例:

- 必要レベル
- 必要HEAT
- 相手HP
- 相手がダウン状態
- 特定技の使用履歴
- キックアウト経験
- 特定位置（Phase 10の位置システム実装後）

### 8.2 発動キャンセル

フィニッシャーが発動した時点で、防御側は以下を使用できる。

- エスケープカード
- リバーサルカード

キャンセル成功時:

- フィニッシャー不成立
- ダメージなし
- フィニッシャーカードを山札へ戻す
- 山札をシャッフルする

エスケープカードとリバーサルカードの機能上の違い（Phase 7で確定）:

**エスケープカード**

- フィニッシャーの発動をキャンセルする
- 攻撃側への反撃ダメージなし
- フィニッシャーカードは山札へ戻してシャッフル
- エスケープカード自体は捨て札
- キャンセル成功時、ラリーは終了する（制御は`activePlayerIndex`のプレイヤーへ戻る）

**リバーサルカード**

- フィニッシャーの発動をキャンセルする
- 攻撃側への反撃ダメージなし
- フィニッシャーカードは山札へ戻してシャッフル
- リバーサルカード自体は捨て札
- キャンセル成功時、**主導権が移動する**（防御側が新しいラリー攻撃側になる。
  ダメージを伴う反撃効果は実装せず、主導権交代のみを効果とした）

open questions 10番（Phase 7で解決、解決済みセクションO参照）。

### 8.3 フィニッシャー成立後

フィニッシャーがキャンセルされず成功した場合、相手は以下の方法でのみ敗北を
回避できる。

- 特殊キックアウトカード
- カード固有の特殊な脱出条件（`cannotEscape`が偽の場合のみ、9〜10章参照）

回避できなければ、残りHPに関係なくフィニッシャー使用側の勝利となる。

**Phase 7で確定**: フォール・ギブアップからの決着回避と同じ考え方を
フィニッシャーにも適用し、返技エネルギー・通常キックアウト・ロープブレイク・
HP消費はいずれもフィニッシャーからの脱出には一切使えない仕様とした
（`escapePending`で有効なのは特殊キックアウトカードのみ）。通常攻防用の
リソースと決着回避手段を明確に分離するという、Phase 6完了後に確立した
設計判断をフィニッシャーにも一貫して適用した形（open questions 9番、
解決済みセクションO参照）。

## 9. フォール

フォール効果のある技が成立した場合、防御側は以下のいずれかでキックアウト
できる。

1. キックアウトカードを使用
2. HPを消費

**返技エネルギーは使えない**（Phase 6完了後の見直しで確定。返技エネルギーは
ラリー中の返技（7章、ダメージ無効化・攻守交代）専用のリソースとし、決着回避
とは明確に分離した。通常攻防用のリソースと決着回避手段を混同させないための
設計判断）。

### 9.1 通常キックアウトと特殊キックアウトの区分（Phase 2で確定）

`KickOutCard` は用途の異なる2種を区別する（`KickOutCardCategory`）。

**通常キックアウト（`normal`）**

- フォール効果のある通常技・固有技に使用できる
- フィニッシャーには使用不可
- 使用後はゲームから除外される（Phase 6完了後の見直しで捨て札から変更。
  捨て札のままだと山札再構築のたびに何度も引き直せてしまい、防御側が
  実質無敵化する問題があったため）
- デッキ内同名2枚まで

**特殊キックアウト（`finisherEscape`）**

- 成功したフィニッシャーからのみ脱出できる（通常のフォールには使用不可。
  通常フォールにも使えると強すぎるためフィニッシャー専用とする）
- フィニッシャー成立後に使用
- デッキ全体で最大3枚、同名1枚まで
- 使用後は除外（Phase 7で実装。通常キックアウトと同じ`removedPile`扱い）

技カードは以下のパラメータを持つ。

```
kickOutThreshold
kickOutHpRate
```

暫定例:
```
kickOutThreshold: 20
kickOutHpRate: 0.5
```

処理:

- 現在HPが `kickOutThreshold` 未満 → カードがなければ敗北
- 現在HPが `kickOutThreshold` 以上 → 現在HPの `kickOutHpRate` 分を消費して回避可能

HP支払いによってHP0になっても、キックアウト自体は成功し、疲労状態（11章）へ
移行する、という暫定案をここに記載する。これは正式決定ではないが、現行
`energy` モードの「HP0は即敗北ではない」という設計哲学（`isDown`/`isExhausted`/
`koStoppage`の区別、Ver.0.9.1）を踏襲する方向性として妥当と考えられる。

## 10. ギブアップ

ギブアップ効果のある技が成立した場合、防御側は以下で回避できる。

1. ロープブレイクカード
2. HPを消費して耐える

**返技エネルギーは使えない**（9章と同じ理由。Phase 6完了後の見直しで確定）。
ロープブレイクカードは使用後、キックアウトカードと同様にゲームから除外
される（捨て札には送らない）。

技カードは以下のパラメータを持つ。

```
giveUpThreshold
giveUpHpCost
```

処理:

- 現在HPが `giveUpThreshold` 未満 → ロープブレイクカードがなければ敗北
- 現在HPが `giveUpThreshold` 以上 → HPを消費して耐えることが可能

`giveUpHpCost` は**固定値**として扱う（Phase 6で決定。`kickOutHpRate`＝
現在HPに対する割合とは方式を変える。open questions J番参照）。

**ダウン限定にしない設計（Phase 6完了後のプレイテストを受けた追加）**:
ギブアップ技を `targetState: down` 限定にすると、常時使用可能な技と
比較優先度で負けやすく、実プレイ・自動シミュレーションの双方で「一度も
使われない」問題が発生した。そのため `targetState: any` としつつ、相手が
ダウン系状態のときに追加威力を得る `downBonusPower` パラメータを技カードに
持たせる設計を導入した（サンプルカタログの「アームロック」に適用済み。
open questions L番）。これは全ギブアップ技に強制する仕様ではなく、
カードごとに選べるオプションである。

## 11. スタンド・ダウン・疲労

レスラー状態:

```
stand
down
fatigued
```

### 11.1 表示

- スタンド: レスラーカードを縦表示
- ダウン: レスラーカードを横表示
- 疲労: ダウン表示に加えて疲労マーカーを表示

### 11.2 ダウン技

技カードは以下のフラグを持つ。

```
causesDown: true
```

成立した場合、相手をダウン状態にする。

### 11.3 対象状態

技カードには対象条件を持たせる。

```
targetState: stand
targetState: down
targetState: any
```

ダウン状態の相手にのみ使える追撃技や、スタンド状態でのみ成立する投げ技を
表現する。

### 11.4 状態の継続

ダウン状態は、次の自分のターンまで継続する。自分のターン開始時に通常は
スタンド状態へ戻す。

## 12. 休息

自分のターンに技を使用せず、自分をダウン状態にすることでHPを回復できる。
回復量はレスラーごとの回復力（`recoveryPower`）を使用する。

暫定仕様:

- 休息したターンは攻撃不可
- ダウン状態になる
- HPを回復力分回復
- 最大HPを超えない
- 休息中の被ダメージ補正なし
- フォールやギブアップへの追加補正なし
- 次の相手ターンにダウン中限定技を受ける危険がある
- 連続休息は禁止しない（連続使用制限は open questions 8番）

## 13. 山札・捨て札

山札が0枚になった場合:

```
捨て札をすべてシャッフル
↓
新しい山札とする
```

山札切れによる疲労ダメージや敗北（現行 `energy` モードの `kExhaustionHpLoss` /
山札切れTKO）は、新モードでは使用しない。

捨て札も空の場合の処理は **未決定事項**（open questions 4番）として記載する。

フィニッシャーの発動キャンセル時のみ、対象のフィニッシャーカードを山札へ戻して
シャッフルする（8.2章）。

**山札再構築の上限（Phase 6完了後に追加、暫定値）**: 1人のプレイヤーが
1試合中に山札を再構築できる回数には上限（`maxDeckReshuffles`、既定2回）を
設ける。プレイテストで「1試合で山札が数百回再構築され、決着が事実上発生
しない」問題が判明したための対応（open questions 21・27・L番参照）。
上限に達した状態でさらに山札が尽きた場合は14章の時間切れ（引き分け）と
同様に扱う。

**キックアウト／ロープブレイクカードの除外（Phase 6完了後に追加）**:
使用したキックアウト／ロープブレイクカードは捨て札ではなく、ゲームから
完全に除外される（山札再構築で戻ってこない）。捨て札のままだと再構築の
たびに何度も引き直せてしまい、防御側が実質無敵化するため（open questions
L番）。実際のプロレスの「最後の粘り」に近い、使い切りのリソースとして
扱う。

## 14. 試合終了条件

### 勝利

- フィニッシャー成功後、特殊回避不能（8.3章）
- フォールからキックアウト不能（9章）
- ギブアップから脱出不能（10章）
- 将来的なKO判定（Phase 10以降で検討、本書スコープ外）
- 反則判定など、今後追加される決着（同上）

### 時間切れ

引き分け。残りHPやHEATによる判定勝ちは行わない（現行 `energy` モードVer.0.9の
「決着は3カウント／ギブアップのみ」という設計哲学を踏襲）。**Phase 6完了後に
初めて実装した**（13章「山札再構築の上限」参照）。ターン数そのものの上限
ではなく、山札再構築回数の上限を時間切れの発生条件とした
（`TechniqueMatchState.isDraw`）。

### HP0

即敗北ではない。

```
HP0
↓
疲労状態
↓
ダウン状態
↓
試合継続
```

HP0時の行動制限は **未決定事項**（open questions 3番）。以下の候補を記載する
（確定しない）。

- 通常どおり行動可能
- 休息しか選べない
- 低コスト技のみ使用可能
- 返技不可
- 自分のターン開始時に強制休息
