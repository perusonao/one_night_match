## 1. ゲームの目的

Technique Match は、通常技・固有技・フィニッシャーをすべて「カード」として
扱う1対1のプロレス対戦ルールである。プレイヤーは技カード・技エネルギー
カード・防御カードで構成された30枚のデッキを使い、技の応酬（攻防）・返技・
フォール・ギブアップ・フィニッシャーを通じて相手を下すことを目指す。

## 2. レスラー

現在4人のレスラーが実装されている（`technique_deck_wrestler_catalog.dart`）。

- 火神アカリ（打撃・スピード型）
- 豪田ミサキ（パワー・投げ型）
- 白銀レイナ（関節・テクニカル型）
- 黒蝶ジャック（ラフファイト・関節型）

各レスラーは以下の情報を持つ（`TechniqueDeckWrestlerProfile`）。

- 基準HP、属性別の技威力補正（フレーバー用途、ダメージ計算には未接続）
- パッシブ能力の説明文（フレーバーテキスト、効果としては未実装）
- 使用可能な固有技カード一覧・フィニッシャーカード一覧
- 立ち絵・テーマカラー

固有技・フィニッシャーはレスラーカードから直接使用しない。該当カードを
デッキへ入れ、手札から使用する。

## 3. デッキ

デッキは1人30枚固定（`kDeckSize` = 30、`TechniqueDeckValidator`）。

カード種別は以下の8種。

```
TechniqueCard（normal / signature / finisher の3区分）
TechniqueEnergyCard
EscapeCard
ReversalCard
KickOutCard（normal / finisherEscape の2区分）
RopeBreakCard
ActionCard（現状未使用）
```

### 3.1 同名カード上限

| カード種別 | 同名上限 |
|---|---|
| 通常技 | 3枚 |
| 固有技 | 1枚 |
| フィニッシャー | 1枚（かつデッキ全体で最大3枚、すべて別名） |
| 技エネルギーカード | 制限なし |
| エスケープカード | 2枚 |
| リバーサルカード | 2枚 |
| 通常キックアウトカード | 2枚 |
| 特殊キックアウトカード | 1枚（かつデッキ全体で最大3枚） |
| ロープブレイクカード | 2枚 |
| アクションカード | 3枚 |

### 3.2 使用可能レスラーの指定

- 通常技・汎用防御カード（技エネルギー／エスケープ／リバーサル／通常
  キックアウト／ロープブレイク）: `allowedWrestlerIds` が空リスト＝全レスラー
  使用可能。
- 固有技・フィニッシャー: `allowedWrestlerIds` の指定が必須（空リストのまま
  デッキへ投入するとデッキ検証エラーになる）。

### 3.3 現行の正式モデルデッキ（Phase 7A）

4人全員分の正式な30枚デッキが `technique_deck_model_decks.dart` に用意されて
おり、以下の構成である（エスケープ・リバーサルは含まない）。

| 種別 | 枚数 |
|---|---|
| 技エネルギー | 13 |
| 通常技（8種×1枚） | 8 |
| 固有技（4種×1枚） | 4 |
| フィニッシャー（2種×1枚） | 2 |
| 通常キックアウト | 1 |
| ロープブレイク | 1 |
| 特殊キックアウト | 1 |
| 合計 | 30 |

デッキの解決優先度（`TechniqueMatchScreen._resolveDeck`）は次の順である。

1. プレイヤーが保存した手動デッキ（あれば最優先）
2. 上記の正式モデルデッキ（Phase 7A）
3. `TechniqueDeckAutoGenerator` による仮デッキの自動生成（保存済みデッキ・
   モデルデッキのいずれも無い場合の最終手段）

## 4. 初期セットアップ

`TechniqueMatchEngine.start`:

- 両者のデッキをシャッフルし、5枚ドローする（`handSize`既定値5）
- 開始直後の状態はプレイヤーA・ターン1・`energySet`フェーズ
- HP・HEATはレスラーの基準値・0からスタート、状態は`stand`

## 5. ターン進行

1ターンの流れ（`TechniqueMatchEngine.endTurn` / `TechniqueMatchScreen`）:

1. ターン開始
2. 自分のレスラーをスタンド状態へ戻す（ダウン・疲労いずれも解除、11章）
3. 使用済みエネルギーを回復する（6章）
4. 1枚ドロー（山札が尽きていれば捨て札を再構築、13章相当）
5. 技エネルギーのセット（6章、1ターン1枚まで）
6. メインアクション: 技の使用（Combo Speedが残っている限り、同じ攻撃側が
   1ターンに複数回技を使用できる。8〜9章）
7. 攻防（ラリー）の解決・決着判定（9〜15章）
8. ターン終了

使用可能な技が1枚も無いフレッシュターン（エネルギー不足・手札切れ等）では、
UI操作なしで自動的にターンが終了する。

## 6. 技エネルギー

自分のターンに、手札の技エネルギーカードを1枚セットできる。

- **1ターンに1枚まで**（`energySetThisTurn`、`TechniqueMatchEngine.setEnergy`
  がエンジンレベルで強制する）
- セットしたカードは永続的にそのプレイヤーの属性別プール（`energyPool`）へ
  加算され、手札から消える（捨て札にもならない）
- 使用済みエネルギー（`spentEnergy`）は自分のターン開始時に全属性まとめて
  回復する
- 攻防（ラリー）中・決着判定待ちの間はエネルギーをセットできない

## 7. 技カード

技カード（`TechniqueDeckTechniqueCard`）は以下のパラメータを持つ。

- `category`: `normal`（通常技）／`signature`（固有技）／`finisher`
  （フィニッシャー）
- `attackEnergyCost` / `reversalEnergyCost`: 使用に必要な属性別エネルギー
  （攻撃用・返技用）
- `power`: 基礎威力、`downBonusPower`: 相手がダウン系状態のときの追加威力
- `speed`: Combo Speedコスト（8章）
- `heatDelta`: 使用時のHEAT変化量
- `targetState`: 使用可能な相手状態（`any` / `stand` / `down`）
- `causesDown`: 成立時に相手をダウンさせるか
- `hasPinEffect` / `hasSubmissionEffect` / `hasFinisherEffect`: フォール／
  ギブアップ／フィニッシャー効果の有無
- `kickOutThreshold` / `kickOutHpRate`（フォール用）、`giveUpThreshold` /
  `giveUpHpCost`（ギブアップ用、13〜14章）
- `finisherRequirements`: フィニッシャーの発動条件（15章）
- `minimumLevel`: 必要レベル（現状レベル変更手段が無いため常に1で判定される、
  20章参照）

使用条件（すべて満たす必要がある）:

- 必要な技エネルギーを支払える
- レベル条件を満たす
- 使用レスラー条件を満たす（固有技・フィニッシャーの`allowedWrestlerIds`）
- 相手の状態条件（`targetState`）を満たす
- 残りCombo Speedが技の`speed`以上である
- フィニッシャーの場合は発動条件（`finisherRequirements`）を満たす

使用した技カードは、成立・防御の成否にかかわらず捨て札へ送る（フィニッシャー
が発動前キャンセルされた場合のみ山札へ戻す、15章）。

## 8. Combo Speed

1ターン内の連続攻撃を制御するリソース。

- 各プレイヤーは`comboSpeed`（既定値10、`defaultComboSpeed`。現状は全
  レスラー共通の暫定値で、レスラーごとの差別化は未接続）を持つ
- 新しい攻防（ラリー）を開始する（攻撃側になる）とき、残りSpeed
  （`rallyRemainingSpeed`）を`comboSpeed`へリセットする
- 技を宣言するたびに`残りSpeed -= speed`。残りSpeedが技の`speed`未満なら
  その技は使用できない
- 攻守交代（返技成功、またはフィニッシャーのリバーサルキャンセル）が
  起きたら、新しい攻撃側の残りSpeedを`comboSpeed`へ全回復する（元の攻撃側の
  残りSpeedは引き継がない）
- フィニッシャーは攻防（ラリー）最後の行動としてのみ使用できる（宣言と
  同時にラリーを終了させるため）。フィニッシャーもSpeedコストを持ち、
  残りSpeedが足りなければ宣言できない

技の`speed`は暫定値（小技1〜2／中技3〜4／大技5〜6／フィニッシャー6〜8を
目安に、`power`帯に応じて機械的に割り当てた値）であり、正式なバランス調整は
未実施（[未決定事項](../design/technique_deck_open_questions.md)参照）。

## 9. 攻防（ラリー）

UI上の表記は「攻防」「COMBO ×N」（内部のフィールド名・エンジンのログ
文字列は`rally`のまま）。

自分のターンに、必要な技エネルギーを消費して手札から通常技・固有技を
使用すると攻防（ラリー）が始まる。以下のいずれかの条件を満たすまで
攻防は続く。

- フォール・ギブアップ効果を持つ技が成立する（防御側の回避判定へ移行し、
  攻防は終了する）
- 攻撃側が追加カードを出さず、攻防の終了を選ぶ
- 攻撃側の手札に、残りCombo Speedの範囲で使用可能な技カードが無い
- 最大反復回数（`TechniqueMatchEngine.maxRallyChain` = 20、無限ループ防止の
  安全弁）に到達する

返技されなかった技（フォール・ギブアップ効果を持たない通常のヒット）は、
成立してもラリーを終了させない。攻撃側は同じ攻撃側のままラリーに残り、
残りCombo Speedが続く限り追加の技を宣言できる（1ターンで技→技→技…という
連続攻撃）。

返技が成功すると、攻守が即座に入れ替わる。新しく攻撃側になったプレイヤー
（元の防御側）は、通常技・固有技のどちらでも次の技を宣言できる。

## 10. 返技

**返技には、防御側の手札に「返技として使用できる技カード」が必要である**
（対応カードなしで防げるわけではない）。

- 手札にあるフィニッシャー以外の技カードは、そのカード自身の
  `reversalEnergyCost`（属性別）を支払うことで、保留中の攻撃への返技として
  使用できる。特定の攻撃技に対応する専用返技カードという1対1の対応は無く、
  汎用ルールとして扱われる
- 返技エネルギーが足りていても、**返技するかどうかは防御側が任意に選べる**
  （エネルギーを温存してあえて技を受ける選択も可能）
- 返技すると技は完全に無効（ダメージ0・HEAT加算なし・ダウンなし）になり、
  使用した返技カードは捨て札へ送られ、攻守が交代する
- 返技しない場合は技が成立し、ダメージ・HEAT・ダウンが即時反映される
- 攻撃側の技カードは、宣言した時点で（成立・返技を問わず）手札から捨て札へ
  送られている

返技エネルギー（`reversalEnergyCost`）は攻防中の返技専用のリソースであり、
フォール・ギブアップ・フィニッシャーからの決着回避には使えない（13〜15章）。

## 11. STAND / DOWN / FATIGUED

レスラーの状態（`WrestlerPosture`）は3種。

- `stand`（スタンド）: 通常状態
- `down`（ダウン）: `causesDown`を持つ技が成立すると付与される
- `fatigued`（疲労）: HPが0に到達すると付与される（ダウン表示に疲労
  マーカーが加わる）

ダウン・疲労状態は、そのプレイヤーの次の自分のターン開始時にスタンドへ
戻る。自分の意思でダウン状態になる手段は存在しない（休息は廃止済み、
[履歴ドキュメント](../history/technique_deck_rule_history.md)参照）。

技カードの`targetState`により、ダウン限定技・スタンド限定技を表現できる
（`down`はダウン・疲労いずれの状態も対象に含む）。

## 12. ダメージ

技が成立するたびに即時適用される（一括適用ではない）。

- ダメージ = `power` + （相手がダウン系状態なら`downBonusPower`）
- HPは0未満にならない。HPが0に到達すると即座に`fatigued`状態になる
  （即敗北ではない）
- 同一ターン中に複数の技が成立した場合、ダメージは技の成立ごとに順次
  反映される（合計値として見れば加算されるのと同じ結果になる）
- `heatDelta`分のHEATが攻撃側に加算される
- `causesDown`を持つ技が成立すると、相手が`stand`状態であれば`down`へ
  移行する（既にダウン・疲労中なら上書きしない）

## 13. フォール

`hasPinEffect`を持つ技（フィニッシャーを除く）が成立すると、防御側は
以下のいずれかで回避できる。

1. 通常キックアウトカードを使用する（`KickOutCardCategory.normal`。
   フィニッシャーには使用不可）
2. HPを消費する（現在HPが`kickOutThreshold`以上の場合のみ。現在HPの
   `kickOutHpRate`分を消費）

**返技エネルギーは使えない**（攻防用のリソースと決着回避手段は明確に
分離されている、10章参照）。

いずれも使わない（使えない）場合、防御側は明示的にフォールを認めて
試合が終了する（攻撃側の「フォール勝利」）。

キックアウトカードは使用後、捨て札ではなくゲームから完全に除外される
（山札が再構築されても戻ってこない）。HP消費でHPが0になっても、
キックアウト自体は成功し`fatigued`状態へ移行する（試合は続く）。

## 14. サブミッション

`hasSubmissionEffect`を持つ技（フィニッシャーを除く）が成立すると、
防御側は以下のいずれかで回避できる。

1. ロープブレイクカードを使用する
2. HPを消費して耐える（現在HPが`giveUpThreshold`以上の場合のみ。
   `giveUpHpCost`は固定値を消費、フォールの割合方式とは異なる）

**返技エネルギーは使えない**（13章と同じ理由）。

いずれも使わない（使えない）場合、防御側は明示的にギブアップして試合が
終了する（攻撃側の「ギブアップ勝利」）。

ロープブレイクカードも使用後はゲームから完全に除外される（キックアウト
カードと同じ扱い）。

フォールとギブアップの効果を同時に持つ技が成立した場合は、フォールを
優先する。

## 15. フィニッシャー

`hasFinisherEffect`を持つ技は、通常の攻防（宣言・返技・フォール／
ギブアップ判定）とは完全に独立した専用の決着フローで処理される。

### 15.1 発動

フィニッシャーカードは、カードごとの発動条件（`finisherRequirements`）を
満たした場合のみ宣言できる。対応キー: `minimumHeat`（自分のHEATがこの値
以上）／`maximumOpponentHp`（相手HPがこの値以下）／`maximumOwnHp`（自分の
HPがこの値以下）／`requiredOpponentState`（相手の状態、`down`または
`stand`）。宣言すると攻撃エネルギーを消費し手札からは除かれるが、
発動前キャンセルに備えてまだ捨て札にはならない。攻防（ラリー）はここで
終了する。

### 15.2 発動前キャンセル

フィニッシャー宣言直後、防御側は以下のいずれかで発動をキャンセルできる。

- **エスケープカード**: キャンセル成功時、ダメージ・HEAT・ダウンは一切
  発生しない。フィニッシャーカードは攻撃側の山札へ戻ってシャッフルされる
  （捨て札にはならない）。攻防（ラリー）は終了する
- **リバーサルカード**: エスケープと同じくダメージ等は発生せず
  フィニッシャーカードは山札へ戻るが、代わりに**主導権が防御側へ移動する**
  （防御側が新しい攻防の攻撃側になり、Combo Speedが全回復する）

いずれのカードも使用後は捨て札になる。

### 15.3 成立

キャンセルされなければフィニッシャーが成立し、ダメージ・HEAT・ダウンが
即座に反映される。フィニッシャーカードは捨て札へ送られる。

### 15.4 成立後の脱出

フィニッシャー成立後、防御側は**特殊キックアウトカード**
（`KickOutCardCategory.finisherEscape`）でのみ脱出できる。通常キックアウト・
ロープブレイク・HP消費・返技エネルギーはいずれも使えない。

脱出できなければ、残りHPに関係なく攻撃側の「フィニッシャー勝利」となる。
特殊キックアウトカードは使用後、ゲームから完全に除外される。

## 16. 勝敗・引き分け

### 勝利条件

- フォールからキックアウト不能（13章）
- ギブアップから脱出不能（14章）
- フィニッシャー成立後、特殊回避不能（15章）

### 引き分け（時間切れ）

山札が尽きて捨て札を再構築する回数には上限（`maxDeckReshuffles` = 2）が
ある。上限に達した状態でさらに山札が尽きた場合、試合は時間切れ引き分けに
なる。残りHP・HEATによる判定勝ちは行わない。

### HP0の扱い

HP0は即敗北ではない。`fatigued`状態へ移行し、試合は続く（自分の次のターン
開始時にスタンドへ戻る）。HP0時の行動制限は未決定事項として残っている
（20章）。

## 17. 試合時間表示

対戦画面・結果バナー・JSON試合ログに表示される「試合時間」（例: `12:30`）は、
**ターン数 × 30秒の演出上の換算値**であり、実時間を計測するタイマーではない
（`formatMatchTime`、`technique_match_json_log.dart`）。1ターン30秒の
リアルタイム制限は存在しない（廃止済み、[履歴ドキュメント](../history/technique_deck_rule_history.md)参照）。

## 18. CPU対戦

CPU対戦は実装済みであり、トップページの「試合を始める」
（`TechniqueMatchSetupScreen`）から標準の導線として選べる（既定選択は
CPU対戦）。

- **CPU難易度は現状Normalのみ**（`TechniqueCpuLevel.normal`。唯一の
  実装レベルで、セットアップ画面にも「Normal（唯一の実装レベル）」と
  明示される）。Level2（中級）・Level3（上級、温存判断）は未実装
- CPUは相手の手札を直接参照しない（自分の手札・双方の公開情報のみで
  判断する）
- 技の評価はダメージ・エネルギー効率・ダウン付与・ダウン限定技への連携・
  フォール／ギブアップ／フィニッシャーへの寄与・技の多様性・返技用
  エネルギーの温存を総合したスコア方式
- 各意思決定ポイントでDecision Trace（`TechniqueCpuDecisionTrace`）を
  生成し、JSON試合ログの`cpuTraces`へ出力する（デバッグ・分析専用、
  勝敗判定には関与しない）
- 「CPU演出速度」（ゆっくり／標準／高速）はCPUの行動を画面上でどれだけの
  速さで見せるかのみを変える設定で、CPUの意思決定ロジック・強さには
  一切影響しない

## 19. JSONログ

`TechniqueMatchJsonLog.build`（`technique_match_json_log.dart`）が試合終了時に
以下の構造を出力する。

- `game`: ゲームID・スキーマバージョン・ルールバージョン・対戦相手種別
  （CPU難易度含む）・開始/終了時刻・勝者・決着理由・ターン数・試合時間表示
  （17章）・山札再構築回数 等
- `players`: プレイヤーごとの集計サマリー（最終HP/HEAT・使用技数・返技数・
  フォール/ギブアップ試行数・フィニッシャー宣言数・キックアウト/ロープ
  ブレイク使用数 等）
- `decks`: 使用したデッキの構成
- `turns`: アクション単位の構造化ログ（技名・ダメージ・HP/HEAT/状態の
  前後比較等）
- `cpuTraces`: CPUのDecision Trace（18章。CPUが関与しない人間同士の対戦では
  常に空配列）

一部のフィールドは休息・タイマーなど廃止済みルールのJSON互換性のために
残されている（LEGACY / deprecated、20章参照）。

## 20. 未決定事項・実験機能への参照

### 未決定事項

以下は未決定のまま残っている。詳細は
[`technique_deck_open_questions.md`](../design/technique_deck_open_questions.md)
を参照。

- HP0時の行動制限
- 手札上限・マリガン・初期手札枚数・先攻1ターン目の攻撃可否
- HEATの上限と役割、レベルシステムを維持するか
- レスラーごとのCombo Speed差別化（現状は全員共通の暫定値）
- 技カードの`speed`値・攻防1回の連続攻撃中に同名技を複数回使えるか
- フィニッシャーのバランス調整（宣言率・決着率が目標レンジ未達）

### 実験機能（Feature Flag、正式ルールではない）

以下は本番のUIやCPUから既定で到達しない、既定OFFの実験的な機能である。
**正式ルールには含まれない**。有効化するUI上のトグルは存在しない。

- **SPEED-vs-COUNTER判定**（`enableSpeedGate` / `enableSpeedCounterGate`、
  既定`false`）: 有効にすると、返技候補の実効SPEED（`calculateEffectiveSpeed`）
  が攻撃技の実効SPEEDを下回る場合に返技できなくなる。既定では常に無効
- **`TechniqueCpuDecisionReason`**: CPUの意思決定理由を機械可読に分類する
  追加フィールド。集計・分析用の付加情報であり、意思決定ロジック自体には
  影響しない

### JSON互換フィールド（LEGACY / deprecated）

以下は廃止済みルールに由来する値で、既存JSONログ・分析ツールとの互換性
維持のため残しているが、次期`schemaVersion`での削除候補である。新しい
用途へ転用しないこと。

- `recoveryPower`（休息廃止により常に無効果）
- `restsUsed`（休息廃止により常に0）
- `timeOverCount`（30秒タイマー廃止により常に0）

廃止済みルールの詳細・変更理由は
[`../history/technique_deck_rule_history.md`](../history/technique_deck_rule_history.md)
を参照。
